# SwifterKit 0.2.0

SwifterKit 0.2.0 is a breaking release that expands the typed Swift surface for
DriverKit and changes the host runtime to push-based event delivery. There is
no migration guide. See the [changelog](../../CHANGELOG.md#020) for the complete
list of changes and breaking API details.

## Highlights

- `coverage/driverkit.json` records 1,117 of 1,117 DriverKit SDK members covered
  with zero gaps across SDKs 24.4, 25.5, and 27.0.
- The fast path runs bounded declarative register programs in the generated
  extension, including DMA rings and host-shared data queues.
- A push-based host control plane signals queued events asynchronously and
  drains them without polling. Host memory can be wrapped, mapped, sliced, and
  composed into chains.
- The typed surface expands across HID, USB, PCI, serial, block storage, MIDI,
  Ethernet networking, audio, SCSI, and video, with service operations, timers,
  watches, and IOReporting available to generated extensions.
- Validation passes with `./scripts/ci/validate.sh` on Xcode 27. Swift 6.1 tests
  pass on macOS and Linux.

## Requirements

- Swift 6.1 or Xcode 16.3 minimum.
- IOKit transport APIs are available only on Apple platforms. Package
  configuration, validation, protocol, and generation code also build on
  Linux.
- Xcode with a DriverKit SDK is required to build generated extensions.

## Breaking changes

This release includes changes to event delivery, runtime protocol negotiation,
connection requirements, typed capability APIs, and error enums. Host
applications must carry the DriverKit user-client access entitlement for the
extension bundle identifier. Read the **Breaking** entries in the
[0.2.0 changelog](../../CHANGELOG.md#020) before upgrading. There is no
migration guide.

## Not run on hardware

Nothing in this release has run on physical hardware. This includes fast-path
programs, DMA rings, data queues, host memory wrapping and mapping, and device
I/O across all capability families. See the [README hardware validation
notes](../../README.md#hardware-runtime-coverage) for the unexecuted paths.
